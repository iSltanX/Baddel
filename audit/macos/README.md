# فحوص macOS اليدوية — تدقيق Copilot

هذه الخطوات **أعدّها المدقِّق ولم يشغّلها**. يشغّلها المالك على جهاز حقيقي ويسجّل النتيجة في الجدول أسفل الملف.
لم يُلمَس فيها شيء من `scripts/device-test` ولا `tccutil` ولا `security`، ولا يُطلب فيها تشغيلها.

## التحضير

1. ابنِ نسخة تطوير من هذا الفرع: `npm ci && npm run tauri dev`. هذه النسخة **debug**، وهذا مقصود لفحص BAD-001.
   ولمقارنة سلوك الإصدار استخدم النسخة المنشورة 2.0.1 من GitHub Releases.
2. فعّل التخطيطين **ABC** و**Arabic**، ثم كرّر الأقسام التي يُشار فيها إلى PC بالتخطيط **Arabic – PC**.
3. امنح إذن تسهيلات الاستخدام من الإعدادات كالمعتاد. لا تستعمل `tccutil`.
4. افتح TextEdit بمستند نص عادي (Format › Make Plain Text) واجعله حقل الاختبار الأساسي.

## ملاحظة عن `BADDEL_LOG`

الشيفرة لا تقرأ متغيّر `BADDEL_LOG` أبدًا؛ `scripts/device-test/run.sh:8,17` يستعمله اسمًا لملفٍّ يُوجَّه إليه stderr فقط.
والسطور لا تُطبع إلا في نسخة debug: سطر نتيجة واحد لكل أمر (`controller.rs:307`) وسطور `trace!` للمسار (`controller.rs:76-82`)، وكلها أعداد وإزاحات وأعلام، لا نص.
فاقرأ منها **النتيجة والمسار والزمن فقط**. نسخة الإصدار لا تطبع شيئًا، وسجلّها الوحيد «الإعدادات › التشخيص».
الطريقة: `npm run tauri dev 2> /tmp/baddel.log`، ثم `grep -E "outcome|path|ms" /tmp/baddel.log`.

## ما يحتاج تفويضًا منفصلًا من المالك

- تشغيل `scripts/device-test/` (يرسل مفاتيح حقيقية).
- أي شيء يمسّ TCC أو Keychain أو التوقيع أو التثبيت أو النشر، ومنها `scripts/install.sh` و`release.sh` و`publish.sh`.
- أي إرسال إلى خادم البلاغات الحقيقي أو `wrangler`.
- ملف `audit/ci/baddel-audit-macos.yml` (مقترح غير مفعّل؛ يُنقل إلى `.github/workflows/` بعد موافقة المالك) المقترح: يحتاج مراجعة المالك وموافقته، ولا يمنح مشغّل GitHub إذن تسهيلات الاستخدام، فهو يثبت البناء واختبارات الوحدة فقط.
